## Adversarial review follow-up

- Review of PR head `ac6e76b` found that A9 stopped at its 80 MiB project-size cap and silently saved the partial index. `ProjectEmbeddingIndex.UpdateAsync` now fails with the configured byte limit and leaves any prior index unchanged. Regressions verify that an oversized first update creates no index and an oversized incremental update preserves the previous index without embedding a partial batch. Current PR head `9440f69` passed 930 portable tests with two opt-in live tests skipped on Windows/Linux/macOS; the portable test summary is available in [Windows CI #37087407959](https://github.com/jay23606/codev/actions/runs/37087407959). The new tests use an injected small byte budget, so they do not allocate an 80 MiB fixture. This machine has only .NET SDK 9.0.305, and the local test command cannot target .NET 10.
- A follow-up adversarial pass found that A9 reused an unchanged embedding when a chunk moved to a different file but retained the old `RelativePath`. Search could then omit the moved chunk if its old file was deleted or misreport where the content came from. The reused entry now takes the current path, with a regression that deletes the old source and asserts the new source is returned without re-embedding its content. Local execution remains unavailable because this host has only SDK 9.0.305. Hosted CI passed this fix at `ec3bf15`: Windows CI [#37088590717](https://github.com/jay23606/codev/actions/runs/37088590717) and four-RID release preview [#37088590810](https://github.com/jay23606/codev/actions/runs/37088590810) succeeded; public release publishing was skipped as expected for a pull request.
- Auto mode intentionally approves all shell command proposals unless an exact deny rule matches. This includes destructive commands and Git commit/push, which run unsandboxed with the user's account permissions; the behavior is explicitly covered by the command-policy tests. The mode must remain clearly disclosed as broad execution consent.
