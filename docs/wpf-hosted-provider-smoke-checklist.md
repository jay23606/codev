# WPF hosted-provider smoke checklist

Use a disposable conversation. These checks call external APIs and may incur charges. Do not use private project data.

- [ ] Open **Connect** beside the model picker. Verify the dialog distinguishes OpenAI API and Anthropic API (Claude), explains separate API billing, says the conversation history is sent, and confirms project files/instructions are not attached.
- [ ] Attempt to connect without checking the acknowledgement; verify the key is not used. Cancel and verify the current model and conversation remain unchanged.
- [ ] Connect with an OpenAI API key and separately with an Anthropic API key; verify available text models appear with the provider name and a streamed reply completes.
- [ ] Verify missing and invalid keys show useful errors without displaying the key. Attempt a failed reconnect while connected and confirm the working key remains active.
- [ ] Select an Anthropic model and send a disposable prompt. Verify the header identifies the hosted provider, Anthropic stays read-only, project context/temperature controls are disabled, and project files/instructions are omitted.
- [ ] Connect OpenAI, start a conversation without attaching a project folder, and enable **Code task**. Accept the prompt/tool-result data and billing notice; verify it does not enable workspace sharing. Send a disposable request and confirm Codev creates and selects a private conversation workspace. Ask OpenAI to list the empty workspace, then create a disposable file and confirm the full proposal still requires review. Verify a command needs approval, a saved exact allow rule applies only to that project, and file edits create recoverable checkpoints. This uses hosted API requests and may incur charges.
- [ ] In the OpenAI Code task, verify the prompt/tool-result acknowledgement is remembered per conversation and **Share workspace** stays separate and off by default. Confirm prompts/tool results can be used while project instructions and source files remain excluded; turn sharing on and confirm the warning explains data scope; turn it back off and ensure the active request stops and later turns omit workspace context. Switch to Chat or Plan and verify project instructions/files remain excluded. Switch to Anthropic and verify Code task is unavailable; switch back to OpenAI and verify it can be enabled again.
- [ ] Close and reopen Codev after saving a hosted key. Verify Codev silently loads the credential and refreshes hosted models; the selected provider/model, Code task mode, workspace-sharing choice, and private workspace remain available without reconnecting. Verify no prompt or project content is sent during startup. Remove the key and confirm hosted requests become unavailable while local Ollama remains usable.
- [ ] Switch the same conversation back to an Ollama model and verify the header returns to local status and local project-context behavior works as before.
- [ ] Connect with a manually entered key, close and reopen Codev, and verify startup discovers hosted models from the stored credential and a blank key field uses the saved key. Replace the key and verify the new one works; use **Remove saved key** and verify the credential is deleted. Removing it should leave Ollama available.
- [ ] Inspect settings, conversation history, and a conversation backup; verify no API key was written. Relaunch with saved keys and verify hosted conversations retain provider/model selection and Ollama remains available offline.
- [ ] Export a conversation with hosted Code task and workspace sharing enabled; import it and verify both hosted data-sharing approvals are off and must be granted again in the new environment.
- [ ] Set `OPENAI_API_KEY` or `ANTHROPIC_API_KEY`, leave the key field blank, and verify the selected environment key takes precedence over a saved key and is not copied to the vault.
